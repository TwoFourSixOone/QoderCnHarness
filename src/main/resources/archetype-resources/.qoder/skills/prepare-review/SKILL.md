# Prepare Review — PR 前变更审计

## 职责

**只负责整理"这次到底改了什么"**，生成 PR 前的评审摘要，帮助人工快速了解变更内容。

本 skill **不做**代码质量评审、架构审查或 SQL 风险检查，这些由其他专项 skill 负责。

---

## 执行步骤

### Step 1：收集变更信息

```bash
# 查看当前变更文件列表
git status

# 查看详细 diff
git diff

# 如果已有暂存内容
git diff --cached
```

### Step 2：分析变更范围

对每个变更文件，分析：
- 文件路径和变更类型（新增/修改/删除）
- 变更行数统计
- 所属模块/分层

### Step 3：关联 OpenSpec Change

检查 `openspec/changes/` 下是否有对应的 change：
- 读取 `proposal.md` 确认需求边界
- 读取 `tasks.md` 确认任务节点
- 核对变更是否覆盖了所有任务

### Step 4：检查隐性约定

读取 `docs/architecture/implicit-contracts.md`，检查本次变更是否涉及隐性约定。

### Step 5：生成评审摘要

按以下格式输出：

```markdown
## 评审摘要

### 变更概述
- **Change 名称**：[change 目录名]
- **核心目的**：[一句话描述]
- **变更文件数**：[N] 个文件
- **变更行数**：+[新增] -[删除]

### 变更文件清单
| 文件 | 变更类型 | 所属模块 | 变更说明 |
|------|----------|----------|----------|
| path/to/file | 新增/修改/删除 | module | 简要说明 |

### 任务覆盖情况
| 任务节点 | 状态 | 说明 |
|----------|------|------|
| task 1 | 已完成/未完成 | ... |

### 测试覆盖情况
- **已覆盖场景**：...
- **未覆盖场景**：...
- **原因说明**：...

### 隐性约定检查
- **是否涉及隐性约定**：是/否
- **涉及内容**：...

### 风险提示
- [需要人工重点关注的区域]
```

---

## 注意事项

- 如果 `openspec/changes/` 下没有对应 change，**显式提醒**：当前变更未经过 OpenSpec 流程
- 如果变更涉及受保护目录（配置文件、SQL 脚本等），**显式标记为高风险**
- 评审摘要应简洁明了，避免冗长描述
