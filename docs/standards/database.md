# 数据库与 SQL 规范

> 本文件定义数据库操作和 SQL 编写的规范，规避数据层风险。

---

## 1. SQL 编写规范

### 基本原则
- 所有 SQL 必须有 WHERE 条件（全表操作需人工审批）
- 批量更新/删除必须有限制条件，**严禁全表更新/删除**
- 禁止使用 `SELECT *`，必须明确指定字段
- 复杂查询必须考虑索引使用情况

### 批量操作红线

| 操作 | 要求 | 风险等级 |
|------|------|----------|
| 批量 UPDATE | 必须有 WHERE 条件，且 WHERE 不能为空 | **极高** |
| 批量 DELETE | 必须有 WHERE 条件，建议先 SELECT 确认 | **极高** |
| 批量 INSERT | 建议使用批量插入，控制单次数量 | 中 |
| TRUNCATE | **禁止 AI 执行** | **极高** |

---

## 2. 索引规范

- 新增查询必须评估是否需要索引
- 联合索引遵循最左前缀原则
- 避免在索引列上使用函数
- 大表查询必须有执行计划分析

---

## 3. 数据库查询权限

### 只读查询（SELECT）— AI 可自主执行

通过 MCP 配置只读数据库连接后，AI 可以**直接执行 SELECT 查询**，无需人工审批：

- 查询表数据、数据分布
- 验证数据是否正确写入
- 分析索引使用情况
- 执行 EXPLAIN 查看执行计划

**约束：**
- MCP 数据库连接必须使用**只读账号**（仅 SELECT 权限）
- 禁止通过 MCP 执行 INSERT/UPDATE/DELETE/DDL
- 查询结果不得包含敏感信息（密码、密钥等），如需查看须脱敏

### 写操作（INSERT/UPDATE/DELETE/DDL）— 必须走流程

所有写操作必须通过以下方式执行：

| 方式 | 适用场景 | 是否需要人工 |
|------|----------|-------------|
| 人工在 Database 面板执行 | 线上数据修复、紧急修复 | ✅ 必须人工执行 |

---

## 4. 数据库脚本管理

- 所有 DDL 变更必须通过脚本管理
- 脚本必须包含回滚方案
- **AI 不得直接修改数据库脚本文件**，需通过 change 流程

---

## 5. 事务规范

- 事务范围尽量小，避免长事务
- Service 层管理事务边界
- 明确事务传播行为
- 异常时确保事务回滚

---

## 6. 高风险操作清单

以下操作需要**人工审批**后才能执行：

- [ ] 修改表结构（ALTER TABLE）
- [ ] 删除表（DROP TABLE）
- [ ] 全表更新/删除
- [ ] 修改配置文件中的数据库连接
